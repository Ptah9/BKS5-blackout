## 3. Запуск

```bash
npm install          # один раз, пока есть интернет
npm run build        # клиент → dist/
npm run cert         # сертификат для локальной сети (нужен для https)
npm start            # https://<ip>:8443
```

Разработка — двумя терминалами:

```bash
npm run dev:server   # http://127.0.0.1:8080
npm run dev:client   # Vite на 5173, проксирует /ws и /api на 8080
```

Проверка, что ничего не сломано: `node tools/smoke.mjs` (статика, рукопожатие,
пинг, мусорное сообщение). Гоняй после любой правки сервера.

Порты: 8443 — продакшен (https+wss), 8080 — dev-сервер (http), 5173 — Vite.

## 4. Жёсткие ограничения

1. **На демонстрации выключают интернет.** Ни одной внешней зависимости в рантайме:
   ни CDN, ни Google Fonts, ни загрузки моделей с сервера при старте. Всё в бандле
   или на диске. Подробный чек-лист — `ПЛАН.md`, раздел «Офлайн-чеклист».
2. **Только локальная сеть.** Никаких облачных сервисов, никаких внешних API,
   включая LLM: модель работает на машине-сервере.
3. **Клиент не знает адреса сервера.** Берётся `location.origin`. Не добавляй
   конфиги с IP — это ломает переносимость между ноутбуками.
4. **Один порт.** Статика и WebSocket живут на одном порту, отдельный порт для сокета
   не заводить.
5. **~10% контента на клиенте.** Мир грузится чанками по близости и выгружается.
   Если добавляешь ассеты — они обязаны идти через `world/chunkManager`, иначе
   счётчик на экране перестанет быть правдой, а это пункт оценки.

## 5. Правила работы

- **Коммит — только с разрешения владельца.** Сначала показываешь `git status`
  и что именно изменилось, потом ждёшь «коммить». Правило появилось после того,
  как агент закоммитил M0 сам.
- **Коммит идёт от имени владельца** — `Ptah9 <ptah_9@icloud.com>`, это задано
  в локальном конфиге репозитория. Не подставляй своё имя ни через `-c user.name`,
  ни переменными окружения: в истории на GitHub не должно быть видно, что коммитил
  агент.
- **Сразу в `main`**, без рабочих ветвей и worktree: хакатон, время дорого,
  ветвление только запутывает.
- Документы и код — по-русски (имена в коде по-английски, тексты и комментарии
  по-русски).
- Не переписывать чужие файлы целиком: точечные правки.
- Не удалять и не переименовывать чужое без явного согласия.
- Файлы UTF-8, переводы строк LF (в репозитории `core.autocrlf=true`, git ругается —
  это не ошибка).
- Новые зависимости — только если можно объяснить, что они дают. На защите спросят
  «почему взяли именно это».

## 6. Архитектура и границы

```
client/            Three.js + TS, собирается Vite в dist/
  src/core/        цикл кадра, ввод
  src/render/      рендерер, свет, материалы
  src/world/       чанки, геометрия, коллизии
  src/game/        игрок, инвентарь, пульс, катсцены, зоны
  src/net/         сокет, протокол, реплика, предсказание
  src/ui/          HUD, панели, графики
backend/server/    Node ESM: статика dist/ + WebSocket + (позже) БД и сценарий
backend/db/        модуль БД (SQLite, файл data/game.db), не отдельный сервис
backend/llm-mic/   отдельный процесс: локальная модель и микрофон
shared/protocol.js имена сообщений, общие для обеих сторон — одна копия правды
tools/             сертификат, доверие, дымовой тест
```

Правила границ:

- Ассеты грузит **только** `world/chunkManager`. Один вход — один счётчик.
- Сообщения парсит и раскладывает только `net/`, сцена читает из реплики.
- Сервер — хозяин мира: сценарий, флаги, инвентарь, позиция в БД. Клиент не может
  выдать себе предмет или объявить, что вышел наружу.
- Катсцены косметические: локальные, сервер их не блокирует, пропуск не влияет
  на других.

## 7. Соглашения по протоколу

- Имена сообщений и коды закрытия — только из `shared/protocol.js`. Поменял имя —
  подними `PROTOCOL_VERSION`, иначе старые вкладки будут молча ломаться.
- Дельты — замена состояния, а не приращение: `{id, x, z}` значит «сейчас он здесь».
- Неизвестное сообщение клиент игнорирует и пишет в консоль, а не падает.
- Тайминги: ввод 20 Гц, дельты 20 Гц, пинг 1 Гц, запись в БД 1 Гц + на событиях.
  Частоты менять только осознанно, они связаны с интерполяцией на 100 мс.

## 9. Окружение и подводные камни

- Windows, Node 24.14, npm 11.9. `openssl` и `mkcert` в системе **нет** —
  сертификат выпускает `tools/make-cert.js` на пакете `selfsigned` (v5, только async).
- `three` не поставляет типы — нужен `@types/three`.
- PowerShell-консоль выводит кириллицу из логов сервера кракозябрами (кодировка
  консоли). На работу не влияет; при отладке сети это мешает, лечится `chcp 65001`.
- Доверие сертификату — `tools/trust-cert.ps1`, кладёт в `Cert:\CurrentUser\Root`.
  Требует явного согласия владельца: это изменение в системе, а не в проекте.
- `certs/`, `dist/`, `node_modules/`, `data/` в `.gitignore`. Перед демо `dist/`
  собирается заново и, если решим, коммитится отдельно — но только с разрешения.
